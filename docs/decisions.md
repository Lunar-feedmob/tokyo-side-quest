# 实现决策记录

普通实现选择和已解决的规格歧义。凡是改变核心范围、会产生费用或改变公开范围的事项，都已单独标注“需负责人确认”。

| # | 决策 | 原因 |
| --- | --- | --- |
| D1 | 本地对象存储使用 **SeaweedFS 4.48**，不用 MinIO | MinIO 已停止发布社区版 Docker 镜像（拉取 `minio/minio` 返回 not found）。代码只依赖 S3 API，生产环境可以换成任意 S3 兼容服务。 |
| D2 | 新增 `APP_ENV`（development / test / production），独立于 `NODE_ENV` | `next start` 总是以 `NODE_ENV=production` 运行。测试替身 AI 和模拟定位只能由显式的 `APP_ENV=test` 打开，且页面持续显示“测试环境”。 |
| D3 | 新增 `neighborhoods` 表 | 规格 §10 有 `/neighborhoods` 接口，但 §8 的数据模型里没有对应的表。 |
| D4 | 参考图库按地点存储（`reference_images.place_id`），发布地点版本时把图片 ID 快照到 `place_versions.reference_image_ids` | 发布后的版本不可变；照片尝试绑定的是它提交时的地点版本。参考图只停用、不物理删除。 |
| D5 | evaluation 缓存键包含：访客、模式、地点版本、参考库版本、图像 SHA-256、provider、模型、模型配置版本、两个提示词版本、评分规则版本 | 落实 §6.9 和 §8.3：缓存按访客隔离，任一版本变化都会产生新的评估。 |
| D6 | 未通过的定位打卡不入库，只把服务端计算的距离和精度返回给用户 | 减少位置数据留存。通过的打卡会短期保存原始坐标（24 小时后由 Worker 清除），之后只保留距离、精度和判定。 |
| D7 | 照片打卡如果附带了用户主动提供的定位，只保存服务端判定的结果（`location_evidence`），不保存原始坐标 | 同 D6。 |
| D8 | 地点有两个状态维度：`places.status`（published / temporarily_closed / …）和版本内容 | 临时关闭的地点仍然显示，但禁止新打卡。Worker 在发奖前会再检查一次状态（§9.3 第 13 条），关闭则返回 `PLACE_UNAVAILABLE`、不发奖。 |
| D9 | 创建分享后，票根会重新渲染以加入真实二维码；渲染期间继续提供旧图 | 规格要求有分享时才显示二维码，且不能放假二维码。 |
| D10 | 删除封面照片时：立即撤销相关分享，票根改用品牌底图重新生成 | §14.2 写的是“进入删除或重新生成状态”，这里选择重新生成。旧的 PNG 会被删除。 |
| D11 | 试玩票根可以生成和下载，但不能创建公开分享链接 | 避免试玩内容被当作真实打卡传播；试玩票根带“试玩纪念”斜标。 |
| D12 | 管理员认证使用 `@node-rs/argon2`（Argon2id）加自建会话表，没有引入完整的认证框架 | 规格要求“成熟认证库处理密码哈希与会话”。哈希用成熟库，会话沿用访客会话同样的哈希令牌模式。登录按客户端和账号分别限流（15 分钟 10 次）。 |
| D13 | 角色分三级：reviewer（只能复核）、editor（内容加复核）、owner（全部，含操作日志） | 规格只要求“管理员角色服务端判定”，这里细化为三级。 |
| D14 | 海报渲染使用 satori + resvg，内置 Noto Sans/Serif CJK SC 子集字体，由 `pnpm fonts:fetch` 按 SHA-256 校验后拉取 | 字体共约 29 MB，不放进仓库。satori 按内容盒计算尺寸，模板已据此调整。 |
| D15 | Claude provider 默认带上服务端拒答回退（`fallbacks: "default"`，beta `server-side-fallback-2026-07-01`），仅对支持的模型生效；SDK 不自动重试，重试由队列负责 | 每次调用都记录在 `ai_calls` 里。**需负责人确认**：回退可能改由另一个模型完成判定；如果不希望这样，从 `ai/anthropic.ts` 删除即可。 |
| D16 | 模型输出先用 Zod 校验，再加业务约束：`matched` 必须至少有一条支持证据、没有冲突证据，且 reasonCode 必须一致 | §6.5 要求不依赖提示词代替校验。校验失败时受控重问一次，仍失败则记为 `AI_OUTPUT_INVALID` 技术错误。 |
| D17 | 首发谷中只对 3 个地点开放照片核验：谷中银座、观音寺筑地塀、冈仓天心纪念公园 | 夕やけだんだん的现有参考图早于旁边 2026 年竣工的公寓；よみせ通り授权参考图不足；根津神社禁止“不参拜只拍照”。这 3 个地点只开放定位打卡，详见 content-provenance。 |
| D18 | 故事 4 个主要节点都设为 `either`；夕やけだんだん暂不开放照片核验，这一节点实际只能用定位完成 | 符合 §5.3“首版主要节点默认 either”，发布检查也允许这种配置。 |
| D19 | 试玩的定位打卡统一使用目标地点坐标作为模拟位置，并标注“模拟定位” | §3.4 要求试玩空间完整可体验；试玩数据与真实数据隔离（I13）。 |
| D20 | 公开的就绪检查接口只返回各项通过或失败；具体缺少哪些配置只在 `/api/v1/admin/health` 显示 | §16.3：对用户按功能降级，具体配置缺项只在后台显示。 |
| D21 | `.env` 放在仓库根目录，web / worker / 脚本共用。Next 通过 `process.loadEnvFile` 读取，已存在的环境变量优先 | 只维护一份配置。 |
| D22 | drizzle-kit 生成迁移时会把 `geography(Point,4326)` 加上引号，导致 SQL 无效 | 已在 `0001_init.sql` 中手动修正。**以后新生成迁移后需要检查一遍。** |

3. 部署位置和 HTTPS 域名。
4. 是否安排人员去谷中实地补拍参考图、校准坐标和半径（当前全部为桌面核对）。
5. 根津神社是否与神社沟通开放照片打卡（目前只开放定位）。
6. 代码推送：当前 GitHub 账号对 `toller892/tokyo-side-quest` 没有写权限，截图是通过 fork 提交的 PR #1。
